## 2. 用户、痛点与目标

- 用户：教学总监、校长、教研组长、多校区教学管理者
- 痛点：教学质量检查常依赖零散听课和主观印象，无法把课堂观察、作业、测评、家长反馈与整改闭环连接起来。
- 目标：围绕一个学科或校区的质量主题，组织证据采样、诊断、问题排序、改进实验和复测。

## 3. 输入契约

| 键 | 名称 | 类型 | 必填 |
|---|---|---|---|
| `supervision_scope` | 督导范围 | string | 是 |
| `quality_goals` | 质量目标 | array | 是 |
| `evidence_sources` | 证据来源 | array | 是 |
| `sample_records` | 样本记录 | array | 是 |
| `previous_actions` | 上一轮整改 | array | 否 |
| `reviewer_roles` | 复核角色 | array | 是 |

## 4. 工作流

1. 确认范围
2. 设计抽样
3. 盘点证据
4. 形成问题树
5. 设计改进实验
6. 分阶段实施检查
7. 复测和关闭

## 5. 阶段状态

| 阶段 | 动作 | 退出成果 |
|---|---|---|
| S1_SCOPE_CONFIRMATION | 确认目标、校区/岗位/课程范围、期限、交付格式和可用资料。 | 任务确认单与最多3个关键缺口 |
| S2_EVIDENCE_INVENTORY | 盘点质量主题与目标、课程与课次、课堂观察/转录、作业与测评样本、教师与班级信息、家长反馈、上一轮整改，标记来源、版本、敏感字段与冲突。 | 证据清单、缺口表和冲突表 |
| S3_PROFESSIONAL_DIAGNOSIS | 围绕围绕一个学科或校区的质量主题，组织证据采样、诊断、问题排序、改进实验和复测。进行专业诊断，形成问题树和优先级。 | 问题树、风险和优先级 |
| S4_SOLUTION_DESIGN | 按确认范围 → 设计抽样 → 盘点证据 → 形成问题树 → 设计改进实验 → 分阶段实施检查 → 复测和关闭设计首选方案和受限备选方案。 | 方案、责任人、完成标准 |
| S5_HUMAN_CONFIRMATION | 由教学负责人/教研组长复核质量诊断、改进实验与教师管理决定；不得替代人事处分。 | 确认记录、未决项和升级项 |
| S6_FINAL_DELIVERY | 生成完整交付成果，执行结构、证据、安全、品牌和独立安装检查。 | 最终成果、范围限制和复盘指标 |

## 6. 核心成果

- `专项督导方案`
- `质量诊断`
- `改进实验`

## 7. 差异化与排重

- 与现有产品：现有课堂观察与学情分析是单点工具；本产品跨多源证据做专项质量督导和闭环。
- 排重检查：部分重叠；使用相同教学证据，但本产品输出质量专项诊断与实验闭环，不提供个人长期教练。
- 独立理由：只安装本 Agent 即可完成专项督导；不强制依赖任何观察量表。

## 8. 安全与人工门禁

- 复核角色：教学负责人/教研组长
- 复核范围：质量诊断、改进实验与教师管理决定；不得替代人事处分
- 不调用外部收费API。
- 不自动修改外部系统、执行退款、审批合同、处分员工或联系外部人员。
- 高风险产品完成状态必须确认人工复核。
